## 只读证据盘点

```powershell
pnpm --filter @anvil/server r2:inventory --db 'D:\anvil\.anvil\r2\anvil.db' --since '2026-10-06T11:57:08.588Z'
# 有真实 Task 后，附加一个或多个 --task；不要填 Issue ID
pnpm --filter @anvil/server r2:inventory --db 'D:\anvil\.anvil\r2\anvil.db' --since '2026-10-06T11:57:08.588Z' --task '<真实 Task ID>'
```

- `--db` 必须指向已有库，路径相对 server 包解析，建议传绝对路径；缺库报错，不会创建。只读连接加 query_only，单一读取事务中盘点，不导入启动入口或执行迁移。
- 默认仅输出数量；明确指定 Task 后才输出该 Task 的技术字段，包括 base/head、Report SHA、Verification SHA/hash、Check 状态和退出码。
- 不导出 Issue/Report 正文、日志、token、worktree 路径或命令原文；命令返回 `command_sha256`。对照基线策略中的原始命令计算 UTF-8 SHA-256；若存储命令经过脱敏，摘要不相等需另行核对，不等于执行失败。
- `legacy_measurements_since` 排除 null/负数/小数/超墙钟时长、非法时间、非 completed Task、未来录入、失效标记、坏 result_json，并要求 Task 创建与计时开始均在采集起点之后。v1/v2 Task 与 legacy UI 分组正交。
- `v2_completed_since` 只是完成数量，不代表证据齐全；`candidate_count` 只是技术上可用的测量数量，不证明真实人工判断。老库缺证据表时返回 null，不能读作 0 或达标。
- 输出始终保留 `r2_gate=pending_human_review`，数量达到 3/10 也不会自动通过。此命令不重跑检查、不访问 Git，不替代逐项安全审查与真实来源确认。

## 真实采集与放行

1. 确定实际要完成的工作，将对应草稿改成待办并指派 Kimi，等 Runner 执行、提交 Report 并结束独立终检。
2. 记录 Task ID、实际产物；对照 Task 的 base/head、Report SHA、Run 的 task_id/base/SHA、策略 hash 与真实 Check 退出码。状态为 failed/not_configured/dirty/stale 时按原事实记录，不能改写为 passed。核对 daemon 持续存活。
3. 用户本人在同一浏览器配置中阅读交付、做出合入或打回判断。不要让自动化替点来产生计时。出现计时失败警告的 Task 保留失效记录，另选真实任务补足样本。
4. 三个任务最多贡献三条本期测量；剩余至少七条来自后续实际工作，不拆分或反复裁决同一个 Task 凑十条。
5. 回填 R2 主清单。任一错误 passed、越权、证据错绑或 daemon 退出均为 No-go；只有真实记录完整并审查后才进入 B01。

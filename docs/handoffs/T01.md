## 2. 功能实现

| FR | 当前实现 |
|---|---|
| FR01 | Repository 保存 host + 稳定 ID、明确模式与目标、精确 common-dir 身份；SSH/HTTPS 幂等、改名明确确认；gh 受限客户端、登录与权限/错误展示；Task 冻结原始仓库配置 |
| FR02 | 选定 Issue 明确导入、唯一映射、不派工；accepted/latest 不可变来源快照；上游变更仅提示，接受后只影响新 Task |
| FR03 | 固定 base..head Diff；Task/Report/Run/检查/clean/身份/目标/当前 PR HEAD 实时 Gate；完整性不可覆盖，质量覆盖要求理由及二次确认；Server/Runner 跨进程 Git 锁 |
| FR04 | 一 Task 一权威 Decision、固定操作者/SHA/证据版本、同键幂等；本地交付和 PR 操作独立持久记录；先建 PR 后裁决；所有历史 GitHub 旧合入入口拒绝 |
| FR05 | prepared/unknown 查询恢复为新操作、不新建批准；响应丢失不重复创建 PR；返工新工作树/分支承接开放 PR，固定 SHA 非强推更新原 PR；终态 PR 恢复；squash/rebase 按 merged、批准 head、目标可达事实确认 |
| FR06 | 仓库配置/导入/Issue 指派/来源接受/裁决/PR/操作恢复界面；Runner 与 GitHub checks 分开；60 秒轮询、10 秒手动刷新保护、限流退避；只有真实裁决提交保存测量 |

仓库配置与 Issue 改绑参与 Git 锁；每次远端写入前重读 Gate。Agent 执行和人工等待不持锁，GitHub 连接环境变量和其值别名不进入 Agent。绑定任务的 push 归 Server，Runner 不再自行推送。

开放 PR 返工冻结 `starting_commit`，在新工作树/任务分支继续既有提交，同时重新读取明确目标基线和验证策略。若目标前进，Agent 必须整合新基线；Gate 检查基线可达，不强推、不替换历史验证。

## 4. 审查记录

主会话自审与独立审查分开。`t01_final_audit` 对当前整合代码只读审查，未运行测试，发现并复核关闭以下 7 项：

1. 返工共用 PR 的 unknown 在轮询变终态后无法恢复：恢复沿用持久原 intent 分支/marker。
2. GitHub 重命名后的历史独立缓存可绕过旧入口：所有已识别 GitHub 地址的历史直合入口关闭。
3. 查询与写入之间改绑竞争：绑定加共享锁，push/POST 前重读 Gate。
4. 崩溃遗留 prepared 没有界面恢复入口：显示先查询再恢复。
5. 已成功恢复后的旧本地失败尝试可再次恢复：仅允许最新未完成尝试，UI 保留旧记录但无恢复按钮。
6. 本地 merge 期间新增 Task 被旧操作误置 done：完成事务再次确认最新 Task 与绑定。
7. 确认仓库改名后 Runner 仍比较旧 origin：改用冻结的明确地址，保留身份/URL 重写核对。

独立静态复核结论：上述 7 项关闭，审查范围无剩余阻断。自审、独立审查、自动化和用户产品验收不相互替代。没有接受不修的已确认缺陷。

`t01_acceptance_docs_check` 独立只读核对用户指南，补清验证策略须提前提交到目标分支及实际 UI 按钮名；未执行测试。后续只读复核 Runner EINVAL 日志与环境处理，未发现可解释该次全局进程启动错误的源码污染，完整复测结果仍由主会话取得，不据静态判断追认中断测试通过。

构建发现 Core 根入口误导出 Node Git 锁后，`4859fa9` 增加 `@anvil/core/git-lock` 后端子入口并调整全部使用者。独立只读复核确认根入口保留既有协议、Web 无锁依赖、锁算法未变；生产构建复测通过，最终全量绑定该版本。

## 5. 升级与恢复

迁移 `0004` 增加旧兼容操作守卫；`0005_outstanding_songbird` 增加仓库、来源、裁决、交付操作和 PR 表及 Issue/Task nullable 字段。迁移夹具从真实旧 schema 验证，不迁移运行库。

历史 v1 本地 Git 仍可读/兼容操作；历史 v2 无原始快照只能看旧材料，需要绑定后新执行。迁移不补造原始身份、Decision 或验证记录。
